# Part 8.1 – Introduction

# System Logs (Complete Professional Notes)

System Logs are one of the most important topics in **Linux Administration, DevOps, Cloud Computing, AWS, System Administration, Technical Support, and Cyber Security**.

Linux automatically records system activities, application events, security events, and hardware messages into log files. These logs help administrators monitor system health, troubleshoot issues, and investigate security incidents.

---

# What are System Logs?

## ✅ Definition

**System Logs** are files that store information about operating system events, application activities, user logins, services, hardware, and security events.

Whenever something happens in Linux—such as a user logging in, a service starting, or an error occurring—it is usually recorded in a log file.

System logs help administrators understand what happened on the system and when it happened.

---

## Real-World Example

Suppose an Apache web server suddenly stops working.

Instead of guessing the problem, a Linux administrator checks the system logs:

```bash
tail -f /var/log/syslog
```

or

```bash
journalctl -u apache2
```

The logs may reveal:

- Configuration errors
- Permission issues
- Missing files
- Service crashes

---

# What is Logging?

## ✅ Definition

**Logging** is the process of recording events generated by the operating system, applications, services, and hardware.

Logs are continuously written into log files so administrators can monitor system activities.

---

## Examples of Logged Events

- User login/logout
- Service start and stop
- Failed login attempts
- System boot
- Kernel messages
- Software installation
- Application errors
- Network activity

---

# What is Log Management?

## ✅ Definition

**Log Management** is the process of:

- Collecting logs
- Storing logs
- Monitoring logs
- Analyzing logs
- Rotating logs
- Archiving logs
- Deleting old logs

Proper log management helps keep servers organized and prevents log files from consuming excessive disk space.

---

## Real-World Use Case

Large organizations generate millions of log entries every day.

Tools such as:

- rsyslog
- Logrotate
- ELK Stack
- Graylog
- Splunk

are commonly used to manage logs efficiently.

---

# What is syslog?

## ✅ Definition

**syslog** is a standard logging protocol used in Linux and Unix systems for collecting and storing log messages from the operating system and applications.

It defines how log messages are formatted and stored.

---

## Features

- Collects system logs
- Stores logs in `/var/log`
- Supports local and remote logging
- Used by many Linux distributions

---

# What is rsyslog?

## ✅ Definition

**rsyslog** (Rocket-fast System for Log Processing) is an advanced implementation of the syslog protocol.

It is the default logging service in many Linux distributions.

---

## Features

- High-performance logging
- Remote log forwarding
- Filtering log messages
- TCP and UDP support
- Secure log transmission
- Log templates
- Database integration

---

## Configuration File

```text
/etc/rsyslog.conf
```

---

# What is journald?

## ✅ Definition

**journald** is the logging service provided by **systemd**.

Instead of storing logs only in text files, journald stores log entries in a structured journal.

---

## Features

- Centralized logging
- Stores boot logs
- Stores service logs
- Stores kernel logs
- Fast searching
- Structured log format

---

# What is journalctl?

## ✅ Definition

`journalctl` is the command-line utility used to view and search logs collected by **systemd-journald**.

It allows administrators to filter logs by:

- Service
- Time
- Boot session
- Priority
- User
- Process

---

## Example

View all journal logs:

```bash
journalctl
```

View SSH logs:

```bash
journalctl -u ssh
```

# Logging System in Different Linux Distributions

| Distribution | Default Logging System | Main Command |
|--------------|------------------------|--------------|
| Ubuntu | journald + rsyslog | `journalctl` |
| Debian | journald + rsyslog | `journalctl` |
| CentOS 7/8/9 | journald + rsyslog | `journalctl` |
| RHEL | journald + rsyslog | `journalctl` |
| Amazon Linux | journald + rsyslog | `journalctl` |
| WSL Ubuntu | rsyslog (optional) / journald (depends on systemd) | `journalctl` or log files |

---

# WSL Important Note

Many WSL installations **do not use systemd** by default.

If you run:

```bash
journalctl
```

You may receive:

```text
No journal files were found.
```

or

```text
System has not been booted with systemd as init system.
Can't operate.
```

---

## Why does this happen?

Unlike a normal Linux installation, many WSL environments do not start **systemd** as the init process.

Since `journalctl` depends on **systemd-journald**, it may not have access to journal logs.

---

## WSL Alternatives

Instead of relying on `journalctl`, you can inspect log files directly using:

View file:

```bash
cat filename
```

View page by page:

```bash
less filename
```

View beginning:

```bash
head filename
```

View end:

```bash
tail filename
```

Monitor logs in real time:

```bash
tail -f filename
```

Search inside logs:

```bash
grep "error" filename
```

> **Note:** If **systemd** is enabled in WSL, `journalctl` will work normally.

# Linux Logging Architecture

```text
Application
      │
      ▼
syslog / rsyslog / journald
      │
      ▼
Log Files
      │
      ▼
Administrator
```

### Explanation

1. Applications generate log messages.
2. `syslog`, `rsyslog`, or `journald` collects the messages.
3. Messages are stored in log files or the system journal.
4. Administrators review logs to monitor, troubleshoot, and audit the system.

---

## `/var/log/syslog`

General system log.

Contains:

- System events
- Service messages
- Application logs

Mostly used in Ubuntu and Debian.

---

## `/var/log/messages`

General system log used by:

- CentOS

Contains:

- System messages
- Service events
- Hardware events

---

## `/var/log/auth.log`

Authentication log.

Records:

- SSH logins
- sudo usage
- User authentication
- Failed login attempts

Mostly available in Ubuntu and Debian.

---

## `/var/log/secure`

Authentication log used in:

- CentOS
- RHEL
- Amazon Linux

Contains:

- SSH activity
- Authentication events
- Security logs

---

## `/var/log/kern.log`

Kernel log file.

Stores:

- Kernel messages
- Driver information
- Hardware events

---

## `/var/log/dmesg`

Stores boot-time kernel messages.

Useful for:

- Hardware detection
- Device troubleshooting

View using:


---

## `/var/log/boot.log`

Contains messages generated during the Linux boot process.

Useful for troubleshooting boot failures.

---

## `/var/log/lastlog`

Stores successful login and logout history.

# Key Takeaways

- System Logs record everything happening on a Linux system.
- Logging is essential for troubleshooting, monitoring, and security auditing.
- Ubuntu and Debian commonly use **journald + rsyslog**, while CentOS and RHEL also use the same logging stack with different default log files.
- `journalctl` is used to read logs managed by **systemd-journald**.
- In WSL, `journalctl` may not work unless **systemd** is enabled.
- Common log files are stored in the `/var/log/` directory.
- Essential commands include `cat`, `less`, `head`, `tail`, `tail -f`, `grep`, `journalctl`, `dmesg`, `last`, and `lastb`.
- Understanding Linux logs is a fundamental skill for Linux Administrators, DevOps Engineers, Cloud Engineers, and Technical Support professionals.

# Example 20 – Clear Journal Logs (Use Carefully)

## ✅ Practical Example

Reduce journal size by removing old entries.

### ✅ Command

Keep only the last **100 MB** of journal logs:

```bash
sudo journalctl --vacuum-size=100M
```

Keep only the last **7 days** of logs:

```bash
sudo journalctl --vacuum-time=7d
```

### ✅ Command Explanation

These commands remove old journal entries while keeping recent logs.

> **Warning:** This permanently deletes old journal data.

### ✅ Expected Output

```text
Vacuuming done...
Deleted archived journal files...
```

### ✅ Real-World Use Case

Free disk space on servers with very large journal databases.

### ✅ Screenshot Command

```bash
sudo journalctl --vacuum-size=100M
```

| Failed Logins | `lastb` |
| Boot Logs | `journalctl -b` |
| Error Logs | `journalctl -p err` |
| Export Logs | `journalctl > system-logs.txt` |
| Live Monitoring | `journalctl -f` |
| Rotate Logs | `sudo logrotate -f /etc/logrotate.conf` |
| Reduce Journal Size | `sudo journalctl --vacuum-size=100M` |

---

> **Interview Tip:** Production Linux servers are commonly monitored using `journalctl`, `tail -f`, `grep`, and `logrotate`. Knowing how to filter logs by **service**, **date**, **boot**, and **priority** is a valuable skill for Linux Administration, DevOps, AWS, and Cloud Engineering interviews.

# Interview Question 1

**What are System Logs?**

**System Logs** are files that record events occurring on a Linux system. These events include operating system activities, application events, user logins, service status, hardware messages, and security-related information.

# Interview Question 2

## ✅ Question

**What is Logging?**

### ✅ Professional Answer

**Logging** is the process of recording system, application, and user events into log files.

Whenever an event occurs, Linux automatically stores information about that event in a log file.

Logging helps administrators understand what happened, when it happened, and why it happened.

### ✅ Example

A failed SSH login is automatically recorded in the authentication log.

# Interview Question 3

## ✅ Question

**What is syslog?**

### ✅ Professional Answer

**syslog** is a standard logging protocol used by Linux and Unix systems to collect, process, and store log messages generated by the operating system and applications.

It defines how log messages are formatted and where they are stored.

### ✅ Example

Typical syslog file on Ubuntu:


# Interview Question 4

It provides high-performance logging with features such as:

- Log filtering
- TCP/UDP support
- Log forwarding
- Database logging

It is the default logging service on many Linux distributions.

Configuration file:

# Interview Question 5
